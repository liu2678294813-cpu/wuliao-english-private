## 73.2 根因：为什么旧 ExamInkSurface 不是正式精读笔系统

旧 `ExamInkSurface`（`src/exam/ExamInkSurface.jsx`）虽然 import 了 `AnnotationToolbar`、
`annotationTools` 与 `inkEngine` 的部分函数，但它的**绘制生命周期**与正式精读完全不同：

```text
旧 Exam（劣化）：
pointerdown → createInkSession
pointermove → renderPreview(stroke)
              = clearRect(整块 preview) + drawInkStroke(整条当前笔画)   ← 每次 move 全笔重画
pointerup   → commitStrokes([...strokes, stroke])
              = renderCommitted() = clearRect + renderInkLayer(全部历史笔画) ← 每笔 commit 全量重绘
```

正式精读（Golden，`CustomDeepReader`）为：

```text
pointermove → coalesced 采样 → appendInkSamples
            → renderViewportPreview(rAF 批处理)
            → appendIncrementalInk（只画新段，绝不 clear）
pointerup   → endInkSession → appendInkPointerUp → collapseTapStroke
            → finalizeInkPath（预览补齐最后段 + 抬笔尾段）
            → shouldUseAppendCommit → append-only 提交（不重画历史）
            → schedulePreviewClearAfterCommit（committed 稳定后下一帧清 preview）
```

因此旧 Exam 即使复用了工具栏与几何工具，其渲染管线仍然是"清屏重画"：
笔画越长、历史越多，move/commit 越卡顿；preview→committed 交接没有
finalize 补齐，存在几何跳变与闪烁风险。这就是"代码像但体验不是"的根因。

## 73.3 Shared Ink Runtime

新建共享核心（从正式精读机械抽取，未改动 inkEngine / inkStability / perfect-freehand /
normalized coordinate 定义）：

```text
src/ink/inkRuntime.js        —— 无 React 生命周期控制器 + 纯决策函数 + 契约导出
src/ink/useStructuredInk.js  —— React 接入层（控制器只建一次，deps 每帧刷新，无 stale closure）
src/ui/AnnotationToolbar.jsx —— 唯一工具栏实现（PdfReader 仅 re-export 兼容）
```

**真正共享的 Runtime 能力**（四个 Surface 完全一致）：

- pointer capture / pointer ownership / lost-capture 处理
- coalesced pointer 采样与去重（`appendInkSamples`）
- normalized coordinate 生成（与精读同一 `pointerPointFromSample`）
- direct-ink + ballpoint 增量 live preview（rAF 批处理，`appendIncrementalInk`）
- pen-up 收尾：`endInkSession → appendInkPointerUp → collapseTapStroke → finalizeInkPath`
- append-only commit（`shouldUseAppendCommit` → 只画新笔画，不重画历史）
- pen-up handoff：`schedulePreviewClearAfterCommit`（committed 稳定后下一帧清 preview）
- normal eraser（结构性重绘）、lasso eraser（`eraseAnnotationsInPolygon`，圈选轨迹不持久化）
- 长按临时橡皮（`startInkLongPressTimer`，620ms，抬笔自动恢复画笔）
- undo / clear / resize / 初始加载 / 历史恢复的结构性重绘路由
- stylus 防滚动守卫（`installPenScrollGuard`）、`isActionTarget` 按钮保护
- 工具偏好（pen size / pen mode / eraser mode）共享同一批 storage key
- telemetry（`ink.stroke_end` / `ink.render` / finalize / commit 计时）

**业务隔离（各 Surface 差异仅限）：**

- Persistence Adapter：精读 `wuliao:deep-ink:*`（localStorage）；普通完形
  `wuliao:cloze-ink:v1:*`（localStorage）；考试 `exam-ink`（IndexedDB）
- Surface Identity：精读 passage/page、完形 `resourceId:clozeId`、考试
  `cloze:main` / `reading:text-1..4`
- 允许的辅助工具：精读含"陌生词"指针工具（unknown），完形/考试不启用

**部署到四个 Surface：**

| Surface | 文件 | 提交策略 |
| --- | --- | --- |
| 正式精读 | `CustomDeepReader.jsx` | tile committed 层 + viewport 固定 preview（适配器注入，机械抽取） |
| 原版 PDF | `PdfReader.jsx` | 单 canvas committed + append-only 提交 |
| 普通完形 | `src/ink/ClozeInkSurface.jsx`（新） | 单 canvas，只覆盖正文区域 |
| 模拟考试 | `src/exam/ExamInkSurface.jsx`（重写） | 单 canvas + exam-ink IDB 适配器 |

## 73.5 Cloze

- **Surface geometry**：`ClozeInkSurface` 只包裹稳定的 `<article class="cloze-passage">`
  （final-read 也使用同一 canonical renderer 与同一 `.cloze-passage` 几何），
  Question Panel 完全不在笔迹坐标空间内。
- **为什么覆盖 Question Panel**：面板高度随 Blank 切换 / AI 卡片 / confidence /
  analysis 持续变化；把动态面板纳入同一坐标空间会造成坐标映射漂移。
- **Canonical Cloze Passage Geometry（修改 1/2）**：
  - 全部正式阶段（first-attempt → self-review → correction → analysis → final-read）
    使用同一个 renderer、同一 `.cloze-passage` 样式（width / font / line-height /
    paragraph margin / blank geometry 完全一致）；旧 `.cloze-final-article` 独立排版已移除。
  - Blank 永远渲染"题号 + 字母/—"，宽度稳定，不随答案、显示模式、阶段变化。
  - `answerDisplayMode="text"` 的完整选项文字改经**绝对定位 popover**（`.cloze-blank-popover`）
    展示，绝不改变正文 inline flow，因此不存在 reflow。
  - E2E（flow14 test 2）实测：作答、显示模式切换、self-review / correction / analysis
    切换后，正文句子/Blank 的 anchor 几何逐像素稳定 → **无可见 ink drift**。
- **阶段持久化**：同一 `wuliao:cloze-ink:v1:<resourceId>:<clozeId>` 跨全部阶段保留；
  切 Blank / 题窗开关 / 阶段切换 / reload 均不丢失（flow14 test 1 验证）。
- **unknown-word 安全（R5）**：不回归。初做/复查无释义入口；correction 只标记；
  analysis / final-read 完整开放。Cloze 陌生词走头部 toggle（业务工具），
  Shared Ink Runtime 不参与阶段权限判断。
- **D+1 / D+7 隔离**：`ClozeReviewSession` 不加载、不挂载任何普通完形笔迹
  （源码契约测试断言无 clozeInk/canvas/stroke 引用）。

## 73.6 Exam

- **Cloze Surface**：`cloze:main`；**Reading Surfaces**：`reading:text-1..4`。
  统一判断函数 `examSurfaceIdForItem(item)`（`src/exam/examInkStorage.js`），
  App.jsx / ExamScreens.jsx / 测试全部复用，杜绝多套实现。
- **source fingerprint（修改 6/11）**：完形组首 item 携带 `passageFingerprint`，
  复用项目统一 `computeFileFingerprint`（SHA-256），输入 = resourceId + passage 文本 +
  blank number + option key/text。确定性；正文/题号/选项任一变化指纹即变；
  未新增 Exam/Cloze 专用 FNV。
- **flush 策略（修改 4/5）**：`navigateExam` 内做 Surface Transaction——
  `examSurfaceFlushDecision` 判定真正 Surface 切换（cloze↔reading / text↔text）
  时先显式 flush previous Surface 并 merge verified inkRef 到 registry，再保存
  `currentItemId`；同 Surface 切题（Q21→Q22）不 flush（避免每题一次 IDB write barrier）。
  Unmount flush 仅作为 crash / 意外导航兜底。flush 失败只标记 `partial`，
  保留 last verified ref，不阻塞答案/计时/导航/会话。
- **交卷（修改 5）**：flush 当前 mounted Surface → merge registry →
  生成最终 `Result.inkRefs`（可含 `cloze:main` + `reading:text-1..4`，只含实际存在
  verified snapshot 的 Surface）→ 进入现有 `submitExam`；
  `create-once` / `resultFingerprint` / timeout fence / `flushWithWatchdog` 全部不变。
- **Ink Registry（修改 7/10）**：`examInkRegistryUpsert` —— valid ref add/update，
  null delete；source-mismatch / damaged / clear / invalid snapshot 后旧 entry 被删除，
  `Result.inkRefs` 不会引用失效历史 snapshot。
- **命名修正**：`EXAM_READING_SURFACES` → `EXAM_INK_SURFACES`（含 `cloze:main`），
  错误文案同步；无 schema bump（见 73.4）。

## 修改 13 补充：Exam Surface Transaction

- `examSurfaceIdForItem` 唯一 Surface 判断（cloze→`cloze:main`，Text N→`reading:text-N`）。
- `examSurfaceFlushDecision(previous, target)`：真正 Surface 切换才 flush previous；
  同 Surface 切题（Q21→Q22）不 flush。
- navigateExam 事务顺序：flush previous → merge verified inkRef → 保存 currentItemId →
  进入 target；flush 抛错/partial 只标记 `partial` 并保留 last verified ref，
  答案/计时/currentItemId/Session 不受影响。
- Unmount flush 保留为 crash / 意外导航兜底，不作正常路径数据保障。

## 修改 13 补充：Exam Ink Registry
