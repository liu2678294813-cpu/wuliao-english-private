## 二、R3 前真实问题（审计发现，非复述提示词）

1. **Planner 与首页重复扫描**：`TodayTasks.jsx` 每次刷新都分别调用 `scanLearningState({force:true})` 与 `buildPlanState()`（内部 `forceScan:true` 再扫一次），一次 refresh 至少两次完整 localStorage 扫描。
2. **Rank 独立扫描**：`getStudyRank()` 自己再 `listUserItems(ACTIVITY_PREFIX)` 全量扫描，与 snapshot 的 activities 数据重复。
3. **写入无失效信号**：reading-flow / translation-progress / cloze-flow / cloze-progress / cloze-translation 写入后没有任何事件，`scanRevision` 机制存在但只能靠 focus/账号切换等被动失效。
4. **事件全部散落**：`window.dispatchEvent(new CustomEvent("wuliao:..."))` 字符串散落在 10+ 文件，无集中类型、无 payload 契约、无 SSR 安全。
5. **AI 请求无外部取消**：`callDeepSeek` 只有内部 timeout AbortController；切换文章/段落/题目后，旧请求 settle 仍会 `setMessages` 写入当前 AI 窗。
6. **词汇通信多套未版本化协议**：`wuliao:vocabulary-route` / `wuliao:vocabulary-static` / `wuliao:vocabulary-back` / `wuliao:hardware-back(-response)` / `wuliao:vocabulary-auto-pronounce` / `wuliao:vocabulary-navigate` 直接裸 `postMessage`，无 namespace/version/type/payload 校验，父端 route 与 iframe 实际 route 靠各自猜测。
7. **App.jsx 词汇 iframe 实现内联**：VocabularyWorkspace（约 180 行 iframe/history/route 细节）与 WorkspaceApp 组合逻辑混在一起。
8. **既有测试日期漂移**：`test-study-planner.mjs` 固定 `TODAY="2026-08-09"` 而用 `Date.now()`（8/10）创建任务，运行到 8/10 后 3 项失败（HEAD 版本上复现确认，非本次引入；已修复为固定时间戳，断言强度不变）。

## 三、实际架构修改

### 1. LearningStateSnapshot（Slice B）
- 新增 `src/learningSnapshot.js`：只读 runtime derived cache，按 username 隔离，返回 `{ username, today, revision, scan }`；提供 `isSnapshotStale()`（stale async 判定）。
- `src/todayTasks.js`：scanCache 固化 revision，新增 `getLearningScanRevision()` / `getLearningScanCount()`（仅内存统计，不暴露给普通用户）；失效事件表加入 `wuliao:learning-state-invalidated` 与 `wuliao:vocabulary-session-updated`。
- 5 个写入方（`saveReadingFlow` / `saveTranslationProgress` / `saveClozeFlow` / `saveClozeProgress` / `saveClozeTranslationProgress`）写入后统一派发失效事件（window 缺失静默）。
- `studyPlannerSources`：`collectStudyCandidates` / `buildPlanState` 支持传入已扫描的 `scan` 复用。
- `TodayTasks.jsx`：一次 `scanLearningState` 同时供 Today 卡片与 Planner（消除双扫）。
- `studyRank.getStudyRank({scan})`：复用 snapshot 的 activities，不再独立扫描。
- App.jsx `Home`：rank 刷新走 `getLearningSnapshot()`。

### 2. App Event Contract（Slice C）
- 新增 `src/events/eventTypes.js`（`AppEvent` 集中 17 个事件名）与 `src/events/appEvents.js`（`emitAppEvent` / `onAppEvent`，SSR/测试安全、CustomEvent 缺失降级、返回 unsubscribe）。
- 生产者统一迁移：userData（account-changed）、readingReview、clozeReview、studyRank、aiLearningRecords、storage（unknown-words）、aiReviewService（translation-review）、CustomDeepReader（ai-request/reader-toast/deep-translation/ai-hint-next/learning-archive-jump）、ClozeReader（ai-request）、AiFloatWindow（ai-hint-next/learning-archive-jump）。
- 消费者迁移：AiFloatWindow 3 处监听、TodayTasks 刷新事件表。
- 业务模块常量（`REVIEW_TASKS_UPDATED` 等）改为引用 `AppEvent` 值，保持既有导出名兼容。
- R1 `panelBus` / Back infrastructure 未动。

### 3. AI Request Lifecycle（Slice D）
- 新增 `src/aiRequestLifecycle.js`：requestId 分配、业务上下文（resourceId/passageId/clozeId/questionId/sentenceId/taskType）跟踪、`setActiveContext` 自动 abort 全部 in-flight、同位置新题目/句子请求自动取代旧请求、`isContextStale()`（entry 已清除/abort 视为过期）。
- `callDeepSeek` 支持外部 `signal`（与内部 timeout 合并，finally 清理监听）。
- 4 个 service 透传 signal：`runTranslationReview` / `runQuestionHint` / `runQuestionDiagnosis` / `runClozeAiTask`。
- `AiFloatWindow`：全部 7 个请求入口接入 lifecycle（quick-translate / translation-review / hint / diagnosis / cloze / explain / chat），settle 后 stale 结果一律丢弃；`aiContext` prop 由 `CustomDeepReader`（resourceId+passageId）与 `ClozeReader`（resourceId+clozeId）注入。
- 未统一 prompt、未合并 cache、未改变 Reading/Cloze 教学语义。

### 4. 组件职责（Slice A，按约束只做必要拆分）
- `src/ui/VocabularyWorkspace.jsx`：从 App.jsx 纯搬迁（DOM/className 完全一致），App.jsx 不再定义词汇 iframe workspace。
- 共享 origin helper 移入 `vocabularyProtocol.js`（`vocabularyUsesHttpMessaging` / `vocabularyMessageTargetOrigin`）。
- CustomDeepReader / ClozeReader / AiFloatWindow / PdfReader 未做 UI 边界拆分（约束 3：不改变 DOM 层级 / hook 生命周期 / ref / Canvas / pointer / 笔迹几何）；笔迹算法与 storage schema 未触碰。

### 5. VocabularyBridge（Slice E）
- 新增 `src/vocabulary/vocabularyProtocol.js`：namespace `wuliao:vocabulary`、version 1、10 种消息类型（READY / NAVIGATE / ROUTE_CHANGED / BACK / SET_AUTO_SPEAK / SET_SHUFFLE / SESSION_UPDATED / HARDWARE_BACK / HARDWARE_BACK_RESPONSE / STATIC_PAGE），payload 形状校验。
- 新增 `src/vocabulary/vocabularyBridge.js`：父端桥，source/origin/namespace/version/type/payload 五重校验，`reset()` 支持账号切换重握手。
- 新增 `public/vocabulary/vocabulary-bridge-adapter.js`：子端 standalone adapter（4 个页面在业务脚本前加载），向父端发新协议，把父端新协议转成既有 window 事件供 app-polish/embedded-vocabulary 继续处理。
- 发送点收敛：app-polish（route 上报 / back / hardware-back-response）、embedded-vocabulary（static 上报 / back / hardware-back-response）。
- 新事件：复习完成（review.js）与背词 3/3（memorize.js）上报 `SESSION_UPDATED` → 父端 emit `VOCABULARY_SESSION_UPDATED` → Snapshot 失效。
- 父端路由单一来源：子端报 `ROUTE_CHANGED`，父端 `handleVocabularyRouteChange` 统一同步 hash 与 AppShell active nav。
- patch 脚本（`patch-vocabulary-bundle.mjs` / `patch-vocabulary-import-integration.mjs`）原样保留。

## 七、性能结果

- 首页一次 refresh：`TodayTasks` 的 Today 卡片与 Planner 从「2 次完整 scan」降为「1 次 scan 共享」。
- Rank：复用 Snapshot 的 activities，不再独立 `listUserItems` 扫描。
- 扫描次数可观测：`getLearningScanCount()` / `getLearningScanRevision()`（仅 dev/测试）。
- AI：切换文章/段落自动 abort 旧请求并丢弃 stale 结果；同位置新题目取代旧题目请求。
- 词汇 iframe：不再无意义 reload（沿用 R1 保活逻辑），route 同步走协议而非猜测。
