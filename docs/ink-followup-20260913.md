## 问题证据与修改

1. 实际 Android 屏幕截图在稳定竖线前段测得抬笔右移 0.51944 个物理像素（DPR 1.875，约 0.27704 CSS 像素）。仅比较 Canvas 源位图时偏差接近零，说明之前的验证没有覆盖最终显示结果。该截图使用 Android 注入的笔事件，不能当作真实手写延迟证据。
2. 候选将预览画布和固定笔迹分块放在同一纸张父层，让父层执行共同的屏幕变换，避免独立 fixed 层的合成差异。保留可视范围预览带、原有采样/笔形/压力和成功提交后才清预览的交接机制；没有修改保存坐标或添加固定补偿。
3. 真实试写时的 CPU 采样发现密集页面每次收笔都会重新 stringify/parse 整页笔迹。快照优化复用已验证的序列化前缀，仅在明确追加时处理新增笔迹；橡皮、撤销等结构变化仍完整重建。存储格式保持原 JSON。高频绘制统计另有独立提交改为有界内存采样、收笔批量提交。
4. v1.0.66 在平板实际合成截图中，稳定竖线的抬笔横移为 0.000373 个物理像素；加入输入交付改进后为 -0.000603 个物理像素，均在测量噪声范围。用户确认“偏移消失”，长按正常。
5. 最终原生改动仅 13 行：真实手写笔/笔尾的 DOWN 事件请求 `requestUnbufferedDispatch`，监听器始终返回 false，由原 WebView 继续处理事件；手指独立滚动不请求该模式。没有预测、改坐标、改平滑、改压力或原生笔迹引擎重写。
