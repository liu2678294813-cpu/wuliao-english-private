# 长篇手写性能修复与验证（2026-09-26）

源码已修复，Android 1.0.71（versionCode 77）安装包已生成。华为 BTK-W00（Android 12）独立测试应用验证通过。正式应用仍为 1.0.70（76），本次未覆盖安装正式应用。

## 问题证据与原因

用户视频显示 2016 英语（一）Text 1 逐段精读中，笔迹积累后滚动、打开 AI 和弹出键盘明显变慢。排查确认以下累积成本：

1. **重复解析历史笔迹。** `displayedStageInk` 在滚动时反复解析其他已完成阶段的整份 JSON。真实样本含 734 笔、22247 个点，JSON 为 3,870,353 字节。桌面 Node 对原函数进行 60 次热调用，发生 60 次大 JSON 解析；修复后为 0 次。该函数 P95 从 39.59 ms 降为 0.03 ms，仅代表 CPU 微基准，不能解释成整机响应速度。
2. **全量遍历与重渲染。** 每块画布遍历和投影全部笔画，翻译区域对每笔重复测量 DOM，落笔还会触发整个阅读区的 React 更新。纸张实际布局不变时，滚动或键盘引起的视口变化也可能重复重画。
3. **历史曲线占用主线程。** 第一轮解析优化后，3000 笔压力样本的真机 CPU 剖析仍发现重复的 303 / 541 / 1098 ms 等长任务，调用栈落在画布曲线回放。主线程被占用时，按钮、滚动、键盘都需要等待。
4. **后台消息复制。** 将绘制移到工作线程后，大批嵌套笔迹点的消息复制仍可能造成停顿。进一步改为转移双精度坐标缓冲区，避免复制完整的嵌套采样对象。

## 具体改动

| 操作示例 | 现在的处理方式 |
| --- | --- |
| 上下滚动已经写满的文章 | 按账号、资料、篇章缓存解析结果；按画布块建立笔画索引；后台回放历史曲线；复用最近看过的画布。 |
| 连续写字、撤销、使用橡皮 | 笔尖即时绘制；按变化通知对应句子；后台结果补上期间新增的笔画；删除和布局变化淘汰过期任务。 |
| 打开 AI、弹出键盘、收起工具栏 | 区分纸张几何变化与单纯视口变化，复用未变化的几何和画布；必要布局变化后准确失效。 |

画布块高度由 2048 调整为 512 CSS px，缓冲区由 2048 调整为 768 CSS px。离屏位图缓存上限 32 MiB，超限释放；主屏幕可见画布另计，实测约 20.2 MiB。缓存失效也处理“布局变化时刚移出屏幕的画布”，防止以后重新显示旧像素。

原始笔迹 JSON、采样点、压感、倾角和区域锚点保持原格式。工作线程仅接收用于绘制的派生坐标，使用 Float64 保留 JavaScript 数值精度；原保存对象不被转移或修改。后台仍调用原 `drawInkStroke`，不抽样、简化曲线或压缩成有损图片。不支持 Worker/OffscreenCanvas 或后台失败时回退到原引擎。

主要文件：`src/CustomDeepReader.jsx`、`src/deepInkGeometry.js`、`src/deepInkRenderCache.js`、`src/ink/inkTileRenderer.js`、`src/ink/inkTileWorker.js`、`src/ink/inkTileTransfer.js`。新增 `scripts/test-long-ink-performance.mjs`，已接入 `test:all`。

| --- | ---: | ---: | --- | --- | --- |
| 734 笔 | 16.674 ms | 0 次 | 0 次 | 1 次，52 ms | 0 次 |
| 3000 笔 | 16.673 ms | 0 次 | 1 次，53 ms | 0 次 | 0 次 |

长任务阈值为 50 ms；0 次不表示操作耗时为零。另一次相同路径的 200 帧往返滚动剖析记录到 0 个长任务，199 个帧间隔中有 1 个超过 45 ms，最大间隔为 50.003 ms。此前同一路径最长主线程任务为 1098 ms。对照版本已包含第一轮解析优化，因此这是后台回放优化的对照，不是完整原始版本的全流程基准。
