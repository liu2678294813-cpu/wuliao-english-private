## 4. 本窗口修复了什么

### P1：旧明文密钥可能跨 endpoint 迁移

早期实现可能把 legacy plaintext Key 自动迁移到不同 Provider endpoint。现已改为只有 legacy profile 与 v2 credential scope 完全一致时才允许迁移；否则保持未绑定，不向新目标发送旧 Key。相关迁移、read-back failure 和跨 endpoint 回归测试已通过。

### Provider 与 Credential 架构

- 新增并统一 9 类 Provider 配置和模型目录处理。
- 将能力判断从 Provider 粗粒度提升到模型级 transport/capability。
- 分离 `webDirectStatus` 与 `androidStatus`，无证据保持 `untested`。
- 将浏览器无 HTTP 响应的 fetch failure 分类为 `runtime_network_compatibility`，不误报 auth/model error。
- 增加 endpoint/region/workspace credential scope 和明确重新绑定流程。
- 保留 legacy Text/DeepSeek 与 Vision 配置的兼容读取，没有批量删除旧配置。

### Secret、Backup 与安全边界

- Android 继续复用现有 SecureStore，并增加 native write/read-back 验证边界。
- 保留 Web user-scoped fallback，同时防止其进入普通备份、导出、遥测、日志和错误文本。
- 增加 Android 12+ backup/data extraction exclusions。
- 增加危险 URL scheme、生产 HTTP 和伪 localhost 的阻断。

### UI 与产品化

- 将 AI 设置重构为“文本 AI / 视觉 AI”独立页签。
- 清理部分创作过程型、重复解释型小字，同时保留安全、隐私、状态、错误和无障碍信息。
- 修复 Exam 紧凑状态栏及其原有测试契约。
- 统一图标、品牌海报、Android Launcher/adaptive/round/monochrome 资源。
- 完成四种目标尺寸的 UI、可访问性和控制台检查。

### 启动页与海报问题

用户反馈的两个根因均已定位并修复：

1. 海报已经生成但没有接入真实进入流程。
2. Android 启动主题把整张 splash 位图作为窗口背景拉伸，同时叠加系统 Splash 图标，造成横屏重复、压扁和标题残留。

修复后：

- 原生层使用 Android 12 / AndroidX 标准 SplashScreen 属性，只承担 WebView 接管前的过渡，不再拉伸全屏位图。
- 横竖屏海报在 HTML 中按方向预加载。
- 海报成为账号恢复和首页计划生成期间的覆盖加载层，带轻量进度动画并支持 reduced motion。
- 加载层没有按钮，不需要点击；真实初始化完成即自动进入首页。
- 登录/初始化失败时恢复到原表单状态，不会永久卡在海报层。

BTK-W00 连续截图证据：

- 约 250 ms：标准深海原生过渡，无重复或压扁图标。
- 约 1.4 s：完整横版海报和加载进度出现，无“进入学习”按钮。
- 约 2.5 s：没有任何触摸操作，自动进入原账号首页。
