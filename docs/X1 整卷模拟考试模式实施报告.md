## Runtime 与模型路由

当前 Codex 主机存在两层不同的模型暴露范围：

- 独立任务的新建/续接接口暴露 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.5`、`gpt-5.4`、`gpt-5.4-mini`。其中 Sol/Terra 支持 `low/medium/high/xhigh/max/ultra`，Luna 支持 `low/medium/high/xhigh/max`，其余三类支持 `low/medium/high/xhigh`。
- 本任务实际使用的协作子智能体 `spawn_agent` 接口只暴露 `gpt-5.6-terra` 与 `gpt-5.6-sol`，两者均支持 `low/medium/high/xhigh/max/ultra`。
- 对 `gpt-5.6-luna` + `high` 的只读子智能体探针返回：`Unknown model gpt-5.6-luna for spawn_agent. Available models: gpt-5.6-sol, gpt-5.6-terra`。

因此 Luna 的准确结论是“当前 Codex 主机可用于独立任务，但当前协作子智能体 runtime 未暴露”，不是“客户端没有 Luna”；探针也未返回额度不足或客户端版本不兼容信息，不能归因为 Plus 额度或客户端版本。实际路由遵循用户指定的降级规则：普通审计/UI/CSS/普通测试使用 Terra medium，核心存储/计时/IndexedDB/Handoff 与本次工具栏实现使用 Terra high，两个架构 Gate 使用 Sol xhigh；Sol 未承担例行实现。

## 最终数据合同

### Exam Session

- 当前快照：`wuliao:exam-session:v1:<sessionId>`。
- 有界恢复：`wuliao:exam-session-recovery:v1:<sessionId>`，只保留 last-good。
- 快照含 `version/revision/updatedAt/fingerprint`；覆盖同一 key。
- 每账号最多一个 active Session；多 active 时进入冲突保护。
- `expectedRevision` 只作为当前 runtime stale guard；跨 runtime 的 Session/Result storage event 会立即使控制器失效并锁定作答 UI。
- 同一 runtime 内的答案与导航修改通过轻量 Promise 队列串行持久化，并始终基于上一笔已保存 Session；快速连续操作不会用旧 revision 自己触发冲突。提交先等待该队列收敛。此机制不增加跨 runtime 锁、lease 或 DAG。

### Exam Result

- `wuliao:exam-result:v1:<sessionId>`，create-once。
- 终态冻结 `resultFingerprint/submittedAt/finalElapsedMs`。
- 缺失 Result 只在终态 Session 指纹完全可验证时重建；不一致时保持 damaged/read-only。
- 计分只使用本地官方答案，输出总分、完形、阅读和 Text 1–4 raw score。

### Exam Handoff

- `wuliao:exam-handoff:v1:<examResultId>:<targetId>`。
- 状态仅为 `selected / started / completed / dismissed`。
- 同状态重复操作幂等；不一致 Backup restore 报 conflict 并保留本地值。
- 最多五个语义 target：完形一项、Reading Text 1–4 四项；不产生题级 Planner 任务。
- 只有显式点击 target 才打开现有 Reader；不导入考试答案，不完成普通学习阶段。

### Exam Ink

- `wuliao-english` IndexedDB 从 v3 升到 v4，只新增 `exam-ink` store。
- 仅 Reading Text 1–4 开放；完形无考试笔迹。
- 每个 `username + sessionId + surfaceId` 只保存当前 strokes、revision、sourceFingerprint 和时间戳；Undo/Clear 原子覆盖。
- 提交时有限时 flush watchdog；超时或部分失败不阻断 Result，记录 `partial/flush-timeout`。
- 普通 Reader 的 ink namespace、schema 和曲线算法未修改。

## 尚需人工确认

自动化已覆盖 Pointer/Ink 生命周期、900px 工具栏尺寸和 Android 实机渲染，但无法替代真实 M-Pencil 的压感/跟手/掌触体验。以下只剩物理人工验收，当前不声称已通过：

设备当前 `dumpsys input` 显示 `ExternalStylusConnected: false`；虽然内核暴露 `huawei,ts_pen` 和 M-Pencil 虚拟输入设备，但本轮无法获得一支已连接的真实笔尖进行人手操作。

1. 用 M-Pencil 在 Reading Text 1–4 各画一笔，切 Text、刷新后确认笔迹恢复且不串篇。
2. 执行 Undo 与 Clear，确认 revision 覆盖保存，普通 Reader 的历史笔迹完全不受影响。
3. 在到时交卷附近持续书写，确认 UI 不冻结，Result 仍生成；若 flush 超时，结果显示 partial/flush-timeout 而非丢失终态。
