**修复内容及理由**

| 优先级 | 已实现的行为 | 原因与实现位置 |
|---|---|---|
| P0 | 闭合、往返和回钩笔画完整保留 | 轻点判断同时检查整笔最大位移 ≤1 CSS px、累计路径 ≤2 CSS px；起终点重合不会直接压成点。[inkEngine.js](D:/codex库/无聊英语/src/inkEngine.js) |
| P0 | 绘制未确认时保留笔画和预览 | 提交、全量补绘只有明确返回 `true` 才确认交接；失败笔画进入独立队列，在后续输入、布局恢复或依赖更新时重试。[inkRuntime.js](D:/codex库/无聊英语/src/ink/inkRuntime.js) |
| P0 | 抬笔、取消、丢失捕获和切页只结束一次 | 在业务回调前解除活跃会话；新笔开始前结束旧会话；触摸不能替换正在书写的笔会话。保存失败保留内存状态和边界重试。 |
| P0 | 坐标在整笔期间一致 | 精读起笔时捕获区域快照，提交时沿用；窗口、画布或纸张布局改变前收尾。作文沿用已有的页面快照和离开前写入确认。[deepInkGeometry.js](D:/codex库/无聊英语/src/deepInkGeometry.js)、各 Surface |
| P1 | 起笔立即出现正常笔宽圆点 | 圆点位于可替换尾层；移动后清除旧圆点，稳定轨迹继续增量绘制，避免起笔墨团。 |
| P1 | 尾端到达最新真实采样点 | 新增轨迹与临时尾段一起更新；抬笔使用相同几何，不再等到抬笔才补出原来遗漏的半段。 |
| P1 | 去掉额外帧等待 | 华为实测表明原来的再次 `requestAnimationFrame` 排队是主要软件等待。Android 圆珠笔现在收到合并并去重的真实采样后立即增量绘制；全量历史不参与每次移动。 |
| P1 | 原始事件与普通移动事件兼容 | 原生事件和 React 包装事件均读取合并采样；能力检测后接入 `pointerrawupdate`，以时间及点属性去重，普通移动事件继续作为后备。有合并采样时不附加父事件的汇总坐标。 |
| P1 | 保存与界面更新避开绘制关键路径 | 保存先获得绘制机会再执行；保留同步离开边界、最新待写快照和现有持久化队列。作文保留逐笔撤销队列。统计延后，非紧急 React 更新使用 `startTransition`。 |
| P2 | 保留约 620 ms 长按套索 | 仅真正的起笔停留能触发；形成有效笔画后，本次会话永久取消长按候选，慢写途中停顿不再转成套索。 |

所有画布统一初始化参数和同步合成通道。默认圆珠笔继续采用固定笔宽；未增加压力门槛，也未改动压力曲线。预测轨迹未启用。

合并事件和原始更新的取舍遵循 [W3C Pointer Events 3](https://www.w3.org/TR/pointerevents3/#coalesced-events)：合并采样可保留更细的真实轨迹，父事件可能经过额外处理；原始更新与普通移动可能包含同一组采样，需要去重。

**性能实测及其边界**

设备：Huawei BTK-W00，Android 12，WebView UA Chrome 114.0.5735.196，DPR 1.875。实际探测存在 `pointerrawupdate` 和 `getCoalescedEvents` 接口；物理 M-Pencil 是否持续产生原始事件仍需真实笔输入验收。

在同一平板上，本次脚本场景测到的刷新间隔中位数约 **16.67 ms（60 Hz）**；设备支持 120 Hz，但不能据此把应用这次测试写成 120 Hz。密集精读页面有 1,100 条历史笔画、约 40,500 个历史采样点。

| 指标 | 保留额外 rAF 等待的中间版 | 最终修复包 |
|---|---:|---:|
| 注入输入到 Canvas 提交 P50 | 13.6 ms | 1.1 ms |
| 注入输入到 Canvas 提交 P95 | 24.2 ms | **1.5 ms** |
| 注入输入到 Canvas 提交最大值 | 48.4 ms | 1.9 ms |
| 采样数量 | 179 | 179 |

另一轮剔除预热的定位实验得到 23.8 ms → 1.7 ms 的 P95 改善，Canvas 描线 P95 约 0.1 ms，未检测到主线程长任务。这些比较用于说明额外帧等待的影响，**不是对原始 1.0.61 的完整性能对比，也不是笔尖到屏幕发光延迟**。未测量电量、长时间发热或真实笔硬件采样成本；直接处理高频采样的耗电与长时间表现需要真笔复测。

**尚需 M-Pencil 人工验收**

1. 连写 `o、0、8`，画方框、回钩，共 100 次；切页后重新进入，检查笔画完整。
2. 轻点、`i` 的点、短横、快速长线和折线各 30 次；观察起笔是否轻松、尾端是否跟随、抬笔是否闪变。
3. 连写 10 分钟，包含慢写停顿、手掌放在屏幕上、主动长按套索；与相近笔宽下的 Notein 对比。外部慢动作录像可判断笔尖到显示的差距，录屏可查看抬笔闪变。

软件验证已覆盖关键保存和几何路径，但不能替代真实笔的掌拒、不同握笔姿态、120 Hz 模式、全部分块边界和长时间热稳定性验收。如仍明显落后，下一步依据真笔数据判断 Android 输入或合成是否成为主要瓶颈，再考虑原生低延迟笔迹层。
