## B. 根因与优先级

未发现需要通过删除学习记录处理的 P0 数据故障。

- **P1**：quick-word 的 AI 结果身份省略模型 / Provider。模型改变时会拿到旧模型答案；旧期待“共享模型”与本次明确隔离要求冲突，改为隔离，静态词典行为保留。
- **P1**：完形独立 32 位 fingerprint / 60 条 FIFO / 全局 in-flight 身份不足。需要沿用已有统一缓存的 SHA-256、账号作用域与独立消费者取消。
- **P1**：缺失 Token 被数值转换成 0、损坏条目可能被当作有效结果、取消和独立 Vision 的统计不完整。未知字段保留 null，缓存异常回退，命中执行原校验。
- **P2**：旧 getAiApiCacheScope 引用不存在的 transportKind，凭据轮换缺缓存版本；改用实际模型协议、endpoint 和绑定版本。
- **P2**：长难句仅在途去重，缺有效评价持久复用；生成的新颖性要求不能用旧句顶替。
- **P2**：资料身份或当前空 / 候选稿位于稳定内容之间，降低公共前缀复用潜力；将动态部分后置，保留全部必要内容。

专项取消测试还证实：两个训练窗口共享评价时，首窗口的生命周期会中断另一个窗口。网络执行现在使用共享取消信号，各窗口独立检查是否仍可消费，保留账号切换拦截。

## D. 实际代码与版本边界

新增 `aiCachePolicy.js`、`aiPromptContext.js` 和纯计算模块 `telemetry/aiCacheMetrics.js`，扩展现有 Provider / ResultCache / Telemetry，没有并行第二套 AI 平台或大型依赖。

- `aiProviderResultIdentity`：Provider、规范化 endpoint、实际协议、凭据绑定作用域和轮换版本、匿名账号范围；完整身份还包含模型、任务、消息 / 图片顺序、temperature、Prompt / Schema 版本和所需资源身份。只有哈希进入 key，密钥不进入缓存文本或遥测。
- `aiReviewCache`：沿用 300 条 / 4 MiB 内存与 2 MiB 持久预算、既有任务条数及 LRU；超大条目只留内存；读写损坏 / 配额异常不阻断有效结果；新增可选 TTL。旧数据不主动清空，新身份隔离旧不充分 key。失效、错误、取消、unsure 和不完整 OCR 结果不写缓存。
- 完形接入同一层，保留旧 namespace 的磁盘条目；SHA-256 新 key 不误用旧 32 位 key。可信 evidence 校验仍限本次白名单，不把“全文存在”当作通过引用校验。
- 阅读 / 翻译 / 词义 / 完形 / 作文 / 长难句的必要上下文没有删减，没有为达到门槛增加无关文本。不同阶段的系统规则不合并，动态问题、作文、译文、当前空后置。
- 长难句生成 v1 保持新请求；评价 v2 允许验证后的语义复用，返回时绑定当前 Attempt / Item / version，命中不伪造新的 Provider 请求。
- 正式作文评分继续由原 Repository 和来源指纹约束。只调整 Prompt 内容顺序与版本，未拿旧评分给新作文。
- 兼容导出 callDeepSeek 已转交统一 callAi，避免独立 fetch 绕过当前模型协议 / Usage / 取消。

新增脚本：`test-ai-cache-optimization.mjs`、`bench-ai-cache.mjs`；新增桌面 / 手机 E2E：`ai-cache-optimization.spec.js`。`package.json` 保留已有测试，并增加 `test:ai-cache`、`bench:ai-cache`，专项测试进入 `test:all`。

## E. 可观测性与费用规则

开发者模式 → AI 缓存，不改变普通学习布局。当前账号在最近 300 条遥测事件的所选窗口中按 Provider / model / 实际 transport / task 展示：内存、持久、词典、业务事件、miss、force、join、HTTP 开始 / 结果 / 取消、耗时、读 / miss / write Token、可用的报告费用和缺失原因。窗口不是账号全生命周期总账。

本地命中率 = (内存 + 持久命中) / (命中 + miss + force + join)。并发合并独立计数，词典和业务 Repository 事件独立计数。Provider 命中率 = 已报告缓存读 Token / 相应可统计输入 Token，按 Token 加权，不对单次百分比取平均。字段缺失、负数、hit > input 或矛盾字段保留 Unknown；不伪装成 0。已有业务 Repository 仍是幂等保存来源，不把它建成重复通用缓存。

费用默认不硬编码价格；OpenRouter 真正返回的 usage.cost 可以按“Provider 报告费用”汇总，其他细项无可靠输入则 Unknown。扩展价格卡必须验证 Provider、model、transport、匿名 endpoint 身份、来源、日期、币种、输入 / 读 / 输出价及写入计费方式。计算器区分“写入价包含输入”和“写入另收费”两类，不能把 Kimi 分项收费套进另一家公式。缺写入口径不能给精确费用；高写入成本可产生负节省，不能强行显示正收益。

遥测只保存匿名账号 / endpoint 身份、任务与模型、计数、Token、耗时和费用字段。不记录 Key、Authorization、原始 Prompt、正文作文或手写识别全文。诊断导出继续沿用现有脱敏。
